# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`torchstrap` trains **ensembles of model replicas in parallel** on PyTorch. Every replica is one slice along a leading "batch" dimension; training is vectorized over that dimension with `torch.func.vmap` rather than looped. Models are run **statelessly**: parameters/buffers live outside the `nn.Module` and are passed in explicitly via `functional_call`. This enables uses like bootstrap ensembles (see `examples/spirals/`), where N independently-initialized replicas train simultaneously and per-replica early stopping / checkpointing is supported.

The headline component is a **fused, batched Adam** (`kernels/adam.py`, driven by `optimizer/adam.py`): a custom `torch.library` op that updates the whole ensemble in **one launch total** — all parameters of all N replicas are concatenated into a single consolidated `(N, T)` buffer (`T` = total per-replica numel), so the hand-written CUDA kernel (`src/torchstrap/kernels/csrc/cuda/adam.cu`, or the C++ CPU kernel `csrc/cpu/adam.cpp`) runs once. Each uses ATen's fused-Adam math **for the device it runs on** — the CUDA kernel `#include`s ATen's `fused_adam_utils.cuh` and calls `adam_math` verbatim; the CPU kernel is a port of `native/cpu/FusedAdamKernel.cpp::adam_math` (no header to include, it lives in a `.cpp`). So an active replica is **bit-identical to `torch.optim.Adam(fused=True)` on that device**, and there is no `(N, *param)` memory overhead.

**`SGD` is the second fused optimizer**, built to the same pattern: `torchstrap::sgd_step_` (`kernels/sgd.py`, `optimizer/sgd.py`, `csrc/cpu/sgd.cpp`, `csrc/cuda/sgd.cu`), bit-identical to `torch.optim.SGD(fused=True)` on the device it runs on (`test/optimizer/test_aten_sgd_parity.py`). Unlike Adam, **both** SGD kernels are ports rather than includes — ATen ships `fused_adam_utils.cuh` in the wheel but there is no `fused_sgd_utils.cuh`, `sgd_math` living in an anonymous namespace inside `FusedSgdKernel.cu`. **`Adagrad` is the third** (`kernels/adagrad.py`, `optimizer/adagrad.py`, `csrc/cpu/adagrad.cpp`, `csrc/cuda/adagrad.cu`), and it completes ATen's **entire** fused family — Adam/AdamW/SGD/Adagrad is all of it. RMSprop, Adadelta, NAdam, RAdam, Adamax, Rprop and ASGD have no fused reference on either device, so nothing after Adagrad can be held to the bit-exactness bar. Its CUDA kernel is an **include** like Adam's (`fused_adagrad_utils.cuh` does ship in the wheel); only its CPU kernel is a port.

**Adagrad's CUDA kernel is compute-bound, not memory-bound, and that is upstream's doing.** `at::native::adagrad_math` takes `const double&` hyperparameters, so the final update — including a **double division** — runs in fp64 on the device. On a 4070 Laptop (1/64 fp64 rate) that dominates everything else: measured at R=1, T=264708, `adagrad_step_` is **335 µs against `sgd_step_`'s 39 µs (8.6×)** for identical byte traffic, and the time barely moves from T=264708 to T=1058832 (335 → 339 µs) because each thread is serialising fp64 latency rather than streaming memory. At R=100 it is 5.1 ms against SGD's 2.4 ms and Adam's 3.2 ms. **At small R the fused path is slower than the Python loop** (R=1: 0.31×); it only wins once there are enough replicas to fill the machine. Do not "optimise" the fp64 away — it is ATen's own function, included verbatim, and narrowing it fails `test_aten_adagrad_parity.py` on the spot. A separate, explicitly-not-bit-exact float32 variant is a legitimate feature to add; it is not a fix to this one.

Source is **src-layout**: the package lives in `src/torchstrap/`, not `torchstrap/`.

## Commands

Uses `uv` (not pip/poetry). Requires Python >=3.13. Both hand-written kernels are compiled **ahead of time at install** into a single extension, `torchstrap.kernels._C`, by a top-level `setup.py` (setuptools + `torch.utils.cpp_extension.CUDAExtension`, `--no-build-isolation` so it links against the torch already in the env). So `uv sync` needs a host C++ compiler for the `csrc/cpu/*.cpp` kernels, and additionally an `nvcc` matching torch's CUDA major for the `csrc/cuda/*.cu` ones — **`uv sync --reinstall-package torchstrap` is the rebuild after any edit under `csrc/`**, nothing picks those changes up on its own. Without a matching toolkit the extension is CPU-only and the op raises from the dispatcher on a CUDA tensor, exactly as `torch._fused_adam_` does on a device ATen has no kernel for. There is **no Python fallback path and no backend selection** — see the dispatch section below.

- `uv sync` — install/sync the environment from `uv.lock`, **and compile `torchstrap.kernels._C`**
- `uv sync --reinstall-package torchstrap` — rebuild the extension after editing anything under `src/torchstrap/kernels/csrc/`. Nothing else picks those edits up; there is no JIT anymore
- `uv run python examples/spirals/spirals_parallel.py` — reference example: a 100-replica bootstrap ensemble driven by the **manual `vmap` loop + callable callbacks** (auto-selects `cuda`/`cpu`)
- `uv run python examples/cnn/cnn_parallel.py` — parallel **CNN** ensemble; a consolidation stress test (many varied-shape param tensors → one `(N, T)` buffer). Auto-selects `cuda`/`cpu`; prints the consolidation footprint, throughput, and held-out ensemble accuracy. Its manual loop uses `cross_entropy` and keeps the integer class labels in their own dtype (no cast on the target).
- `uv run pytest` — the test suite (~2 s; CUDA tests skip cleanly without a GPU)
- `uv run python <file>` — run any script in the env
- `uv run pyright src/torchstrap` — type check (configured against `.venv`)

**Tests are pytest**, configured in `pyproject.toml` (`testpaths = ["test"]`). Every kernel test takes the parametrized `device` fixture from `test/conftest.py`, so it runs once per device and the CUDA half *skips* rather than silently vanishing on a CPU box — `uv run pytest -k cuda` is the way to check what actually ran there. Anything that writes to disk takes `tmp_path`; nothing in the suite may leave files in the repo.

`bench_*.py` are **not** collected — they report numbers rather than asserting them, and are run directly (`uv run python <path>`).

- `test/optimizer/test_inplace_adam.py` — parity vs `torch.optim.Adam` (consolidated `(R,T)` op API)
- `test/optimizer/test_aten_fused_parity.py` — **bit-exact** (`torch.equal`) vs `torch._fused_adam_`/`_fused_adamw_`, **on both CPU and CUDA against that device's ATen kernel**; the authoritative numerics gate. Covers ATen's vectorized and ragged CUDA access patterns, and on CPU both the `at::vec` body and the ragged `T % Vec::size()` tail (T ∈ {64, 45, 1000}). Its `f32()` helper is load-bearing: torchstrap carries hyperparameters as float32 tensors while ATen's CPU kernel keeps them in `double`, so the test pre-rounds them or the comparison would be of different numbers
- `test/optimizer/test_cpu_cuda_parity.py` — CPU vs CUDA, incl. the per-replica `distinct_hparams` sweep; also runs `torch.library.opcheck`. **Tolerance-based by design** — CPU and CUDA are deliberately not bit-equal (see below)
- `test/optimizer/test_inplace_adam_masking.py` — per-replica freeze semantics
- `test/optimizer/test_inplace_adam_vmap.py` — `vmap` composability of the op, plus `case_strided`: a non-contiguous `(R, T)` view (a transposed `(T, R)` allocation) must match the contiguous result. This is the layout `movedim(d, 0)` produces for `bdim != 0` and the only coverage of either kernel's strided path — `in_dims=0` makes the movedim a no-op, so the main case never reaches it. **CUDA is asserted bit-identical** (same per-element `adam_math`, only addressing differs); **CPU is a tolerance**, because there contiguous goes through `adam_span_vec`'s `at::vec::fmadd` and strided through `adam_span_scalar`'s multiply-then-add — ATen's own vec-vs-tail inconsistency, reproduced on purpose, worth ~1 ulp
- `test/optimizer/test_state.py` — Adam ensemble vs `torch.optim.AdamW` parity (the current `State`/`Adam.init` API)
- `test/optimizer/test_aten_sgd_parity.py` — the SGD equivalent of `test_aten_fused_parity.py`, and the authoritative gate on both SGD ports. Same `f32()` pre-rounding, same T ∈ {64, 45, 1000} / {64, 45} sweeps, plus `momentum`/`dampening`/`nesterov`/`maximize` rows
- `test/optimizer/test_inplace_sgd.py` — vs `torch.optim.SGD` per replica, incl. the `distinct_hparams` sweep and `test_zero_momentum_replica_inside_a_momentum_call`
- `test/optimizer/test_inplace_sgd_masking.py` — SGD freeze semantics, incl. `test_replica_frozen_before_its_first_step`: a replica frozen at `state_steps == 0` must keep a pristine momentum buffer and, when thawed, run its *first* step. This is why SGD carries a `(R,)` step counter at all — ATen's `is_first_step` is one host bool for the whole call
- `test/optimizer/test_inplace_sgd_vmap.py` — `vmap` composability plus the strided `(R, T)` case, same split as Adam's (CUDA bit-identical, CPU a tolerance)
- `test/optimizer/test_cpu_cuda_sgd_parity.py` — CPU vs CUDA for SGD + `opcheck` (both the depth-3 and depth-2 instantiations). One tight tolerance rather than Adam's split one: SGD's two upstream formulations differ only in fma placement, with no double-precision bias correction to diverge over
- `test/optimizer/test_state_sgd.py` — SGD ensemble vs `torch.optim.SGD` end to end, over the momentum/dampening/nesterov/weight-decay grid; also asserts the momentum buffer exists iff momentum != 0, and that `nesterov` validation fires
- `test/optimizer/test_aten_adagrad_parity.py` — bit-exact vs `torch._fused_adagrad_` on both devices. Sweeps `lr_decay` specifically, because it is the only thing that makes `corrected_lr` depend on the step count — and torchstrap derives that from its own `(R,)` counter rather than ATen's per-tensor `state_steps`, so a step-indexing error is invisible at `lr_decay = 0`
- `test/optimizer/test_inplace_adagrad.py` — vs `torch.optim.Adagrad` per replica, incl. `distinct_hparams` and `initial_accumulator_value`
- `test/optimizer/test_inplace_adagrad_masking.py` — Adagrad freeze semantics, incl. `test_frozen_clock_does_not_decay`: because `corrected_lr` reads the step counter, a frozen replica whose clock kept ticking would resume on a decayed lr it never earned. The test asserts its post-thaw step is bit-identical to a never-frozen first step
- `test/optimizer/test_inplace_adagrad_vmap.py` — `vmap` composability plus the strided `(R, T)` case
- `test/optimizer/test_cpu_cuda_adagrad_parity.py` — CPU vs CUDA + `opcheck`. **One tolerance, not Adam's split one**: the plan predicted Adagrad would need a visibly looser bound because of the fp64/fp32 split, and measurement said otherwise — max abs 1.2e-7, max rel 7.1e-7, with `state_sums` usually bit-identical. Adagrad's update is short and well conditioned, with nothing like Adam's `1 - beta2**step` cancellation
- `test/optimizer/test_state_adagrad.py` — Adagrad ensemble vs `torch.optim.Adagrad` end to end, incl. `initial_accumulator_value`
- `test/callbacks/test_callable_callbacks.py` — the callable callbacks, CPU+CUDA (freeze, checkpoint restore, pinned-async `Snapshot`, freeze-aware LR clock)
- `test/utils/test_tensor_batch_sampler.py` — `TensorBatchSampler` contiguous-slice rewrite: equivalence vs the old gather. The speed claim is `bench()` in the same file, deliberately not a test
- `test/utils/test_conv2d_collapse.py` — `_collapse_kernels` lands an S×S grid on exactly 1×1
- `test/test_batch_weight.py` — per-replica batch size is `input.shape[1]`, not the replica count (a real past bug), and weighted != unweighted epoch mean on uneven batches
- `test/test_consolidation_alignment.py` — the consolidated `T` is padded to `_CONSOLIDATION_ALIGNMENT`, `(N, 0)` stays `(N, 0)`, the offset-table views never cover the pad, and the pad lanes of `params`/`grads`/`exp_avgs`/`exp_avg_sqs` are still **bit-zero** after training. That last one is the load-bearing invariant: a live pad could leak a NaN
- `test/test_smoke_state.py` — end-to-end `StatelessModule.init` → `vmap(grad)` → `apply_gradient`
- `test/optimizer/bench_inplace_adam.py` — benchmark, no flags. Includes a 75%-frozen row to show the early-exit win
- `test/optimizer/bench_adagrad.py` — the same for Adagrad; its docstring records the fp64 numbers above
- `test/optimizer/bench_sgd.py` — the same for SGD, with and without momentum. It sleeps 0.5 s before each CUDA row on purpose: without that, a row late in the sweep is measured on a downclocked card (R=100 with momentum read 10.4 ms bimodal instead of a steady 2.4 ms)
- `test/utils/bench_conv2d_collapse.py` — the collapse-head vs global-avg-pool accuracy study (minutes; trains 6 ensembles)

`test/backups/*.bak` are old copies, not live code.

**Examples never write to the repo.** Both take `--outdir`, defaulting to `<script dir>/out/` (gitignored); `spirals_parallel.py` also takes `--show/--no-show`. Do not reintroduce a bare `savefig("loss.png")` — it lands in whatever directory the script was run from.

`.env` sets `UV_TORCH_BACKEND=auto` so uv auto-selects the torch wheel (CPU/CUDA). **There is no backend selection at all** — the device decides, via the dispatcher, exactly as it does for `torch._fused_adam_`. `set_cpu_backend`/`set_cuda_backend`/`get_*`, the `_JitExtension`/`_NativeBackend` load state machine, the lazy-registration bootstrap and the reference PyTorch implementation are all **gone**; do not reintroduce them.

Building the CUDA kernel needs **nvcc matching torch's CUDA major** plus a host compiler that toolkit accepts (CUDA 13.x caps at GCC 15). When `setup.py` finds none it simply omits every `cuda/*.cu` from the sources and prints what it chose; the CUDA keys are then unclaimed.

## Architecture

The four core abstractions interlock; understanding one in isolation is misleading.

**`StatelessModule` (`stateless.py`)** — a thin stateless wrapper around a base model moved to the `meta` device (it holds no real weights). `StatelessModule.init(model, optimizer, *args, num_replicas=N, init_randomness="same"|"different", optimizer_kwargs=…, **model_kwargs)` returns a **2-tuple `(module, state)`**: `_init_models` builds N replicas (`"different"` calls the factory N times for distinct weights; `"same"` deep-copies one base), `State.from_models` stacks (`torch.func.stack_module_state`) and **consolidates** them, and `optimizer.init(state, **optimizer_kwargs)` populates the optimizer state. `*args`/`**model_kwargs` (e.g. `layer_sizes`, `input_transform`, `dropout_prob`, `device`) flow to the **model constructor**. `forward(params, buffers, *args)` is just `functional_call(base_model, (params, buffers), args)`. **There is no built-in training driver** — `fit`/`predict`/`infer`/`compile`/`notify` were all removed. Training is a **manual `vmap` loop the caller writes**: `grad_loss = vmap(grad_and_value(loss_fn, argnums=0), in_dims=(0,)*k, randomness="different")`; per batch `grads, loss = grad_loss(state.params_dict, state.buffers_dict, x, y, w)` then `Adam.apply_gradient(state, grads)` (see `examples/spirals/spirals_parallel.py`, `examples/cnn/cnn_parallel.py`, and `jet-angularity-study/omnitrain.py`). Inference is the same vmapped forward under `torch.inference_mode()`; dropout is toggled via `module._base_model.train()/.eval()`.

**Host↔device sync discipline.** Keep the per-batch loop on-device: collect `loss.detach()` (no `.cpu()`) into a list and reduce once per epoch (e.g. torchstrap's `EpochScore`). The persistent `History` (`history.py`) is provably host-only — `append_batch` **enqueues** the (possibly on-device) value into a transient per-epoch `_batch_queue`, and **the caller** calls `history.flush_epoch()` once per epoch to **drain the whole epoch's queued batch metrics in one bulk transfer** (per key: `torch.stack` → non-blocking D2H into pinned memory → a single `current_stream().synchronize()`). Net: **one device→host sync per epoch instead of per batch** — keep new per-batch code off the host (no `.item()`/`.cpu()`/`.tolist()` in the inner loop). The callable callbacks that sync (EarlyStopping/Checkpoint) do so at most once per epoch.

**`State` (`state.py`)** — all training state, decoupled from the module, is one **frozen `tensordict.TensorClass`** (`class State(TensorClass, frozen=True)` — proper subclassing, not the `@tensorclass` decorator). `State.batch_size` **is** the `(N,)` replica dimension. Fields: `params` / `buffers` — **bare `(N, T)` tensors**, replica-major consolidations (row `i` == replica `i`; `T` = total per-replica numel **rounded up to `_CONSOLIDATION_ALIGNMENT` = 4**) built by `consolidate_params_and_bufffers_dict` (`torch.cat([leaf.reshape(N, -1) …], dim=1)`); `param_meta` / `buffer_meta` — `NonTensorData`-wrapped offset tables `[(name, shape, off, numel), …]`; `param_buffer_dtype`; `optimizer_state` — a **plain keyed `TensorDict`** (not a typed subclass); `active_mask` — `(N,)` bool; `grads` — an `init=False` `(N, T)` buffer laid out exactly like `params`. **The cat is the source of truth** — nothing is re-consolidated through tensordict, so per-replica `lr`/`active_mask`/freeze are exact. `State.params_dict` / `buffers_dict` are read-only `@property`s returning `{name: flat[..., off:off+n].view(N, *shape)}` — **aliased views** rebuilt each access (frozen forbids caching), fed to `functional_call`. `flat_params`/`flat_grads` return the bare buffers; `_consolidated_grads` is a `TensorDict` of aliased grad views (`consolidated_dict_view` is the shared helper). Constructed via `State.from_models(modules)`.

**`frozen` is load-bearing**: it forbids *rebinding* a field (`state.active_mask = x` → `FrozenInstanceError`) but still allows *in-place* leaf mutation (`state.active_mask.fill_(True)`, `state.active_mask[idx] = False`, `state.optimizer_state["lr"].copy_(x)`, the fused op's in-place writes). This enforces "mutate in place, never rebind". Aliasing invariant: `TensorClass` keeps leaves **by reference** (no clone), so every `params_dict[name]` view shares the one `(N, T)` `params` storage; restore uses `state.copy_` / masked `state[idx] = …` (in place) so identity survives. `__post_init__` is **idempotent** (sets `active_mask`/`grads` only when absent) so the tensorclass ops that reconstruct the instance (`.cpu()`, `.detach()`, `.clone()`, `state[idx]`) don't re-run it against the now-locked graph. `add_optim_state(key, value, per_param=)` (tensorizes via the plum-dispatched `like_tensor`) and `add_optim_meta(key, value)` (stores a `NonTensorData` flag) add optimizer entries by unlocking/relocking the frozen graph.

Which replicas are still training is the **`(N,)` bool field** `State.active_mask` — the fused optimizer consumes it directly with no per-step host→device copy; `EarlyStopping` freezes replicas by masking it in place (`active_mask[idx] = False`), and re-arm code reactivates with `active_mask.fill_(True)`.

Checkpointing writes a **TensorClass memmap directory** (`Snapshot.to_file` → `state.memmap(dir)`; `from_file` → `State.load_memmap(dir)`). `Snapshot` (`callbacks/training.py`) is a CPU-resident `State` mirror built `state.detach().cpu().clone()` — the **`.clone()` is load-bearing** (on a CPU live state `.cpu()` is a no-op that would otherwise alias live storage). `update(state, mask)` brings the `(N,)` mask to host first and **skips the whole D2H when no row improved**; otherwise it gathers the improved rows on device, copies them **non-blocking into a reused pinned staging buffer** (`staging[:k].copy_(g, non_blocking=True)` — fancy indexing returns a *copy*, so the async copy must land in the plain `[:k]` slice-view), one `current_stream().synchronize()`, then a host-side masked `__setitem__` scatter into the mirror — the same pinned-async discipline as `History.flush_epoch`. `restore_to_live(state, mask)` writes masked rows back in place; `mask=None` is a whole-state `state.copy_`.

**`Adam` (`optimizer/adam.py`)** has no optimizer-state class of its own — `Adam.init(state, *, lr, beta1, beta2, eps, weight_decay, amsgrad=False, maximize=False, decoupled_weight_decay=True)` populates `state.optimizer_state` (the plain `TensorDict`) in place: the **per-replica `(N,)` hyperparameter vectors** `lr`/`beta1`/`beta2`/`eps`/`weight_decay` (via `add_optim_state`; broadcast as `(N,1)` over the `T` axis in the kernel), a **single shared `(N,)` `state_steps`** counter (all params step in lockstep), the **consolidated `(N, T)` moments** `exp_avgs`/`exp_avg_sqs` (+`max_exp_avg_sqs` if `amsgrad`, laid out like `params`), and the **static flags** `amsgrad`/`maximize`/`decoupled_weight_decay` stored as `NonTensorData` via `add_optim_meta` (auto-unwrapped on read; they ride through `memmap`/masked-select). `Adam.update(state)` reads those flags back from `optimizer_state` (so `apply_gradient`, which calls `update(state)` arg-less, honors the configured AdamW/amsgrad/maximize variant), pulls the consolidated param/moment buffers + shared step, and dispatches the fused op **once** over the whole ensemble — no per-parameter loop.

**beartype + TensorClass:** `src/torchstrap/__init__.py` runs `beartype_this_package(conf=BeartypeConf(claw_skip_package_names=("torchstrap.state", "torchstrap.optimizer.adam")))`. The skip is **required**: otherwise the claw decorates the TensorClass-generated `__getitem__`/`__setitem__` and enforces tensordict's too-narrow `item: NestedKey` hint, which **rejects the Tensor (fancy) indexing** the masked per-replica row transfers depend on. These two modules get their type-safety from typed `TensorClass` fields + `frozen` instead of beartype. Do **not** annotate-and-rely-on beartype inside them.

**Optimizers are classes, not instances (`optimizer/`)** — `GradientTransformation` is a **metaclass** that requires an optimizer class to define both an `init` and an `update` classmethod (enforced at class-creation time); `Adam` is `class Adam(metaclass=GradientTransformation)`, as are `SGD` and `Adagrad`. The metaclass also provides `apply_gradient(cls, state, grads)`.

**`SGD` (`optimizer/sgd.py`)** follows `Adam`'s shape exactly: `SGD.init(state, *, lr, momentum, dampening, weight_decay, nesterov=False, maximize=False)` puts the per-replica `(R,)` vectors `lr`/`momentum`/`dampening`/`weight_decay` and the shared `(R,)` `state_steps` into `state.optimizer_state`, allocates the consolidated `(N, T)` `momentum_buffers` **iff momentum is non-zero** (ATen's depth 3 vs 2), and stores `nesterov`/`maximize`/`has_momentum` as `NonTensorData` via `add_optim_meta`. Two things ATen structurally cannot do: `is_first_step` is **per replica**, derived from `state_steps` (upstream has one host bool, which would hand a replica frozen before its first step an uninitialised momentum buffer on thaw); and whether the buffer exists is a call-level decision while its momentum *value* stays per-replica, so a sweep including `momentum=0` is expressible — those replicas get plain SGD arithmetically, since `0*buf + 1*g == g`.

**`Adagrad` (`optimizer/adagrad.py`)** is the simplest of the three: `Adagrad.init(state, *, lr, lr_decay, weight_decay, eps, initial_accumulator_value=0.0, maximize=False)` puts the per-replica `(R,)` vectors `lr`/`lr_decay`/`weight_decay`/`eps` and the shared `(R,)` `state_steps` into `state.optimizer_state`, allocates the consolidated `(N, T)` `state_sums` (always — ATen's Adagrad `depth` is hardcoded 3, there is no amsgrad-style variant), optionally seeds it from `initial_accumulator_value`, and stores `maximize` via `add_optim_meta`. The step counter is not bookkeeping here: `corrected_lr = lr / (1 + (step - 1) * lr_decay)` reads it, so the freeze mask holding a replica's clock still is a **correctness** property, not just a saving.

The whole ensemble is updated in **one fused call, not a Python loop over replicas** (this was the central change of commits `4ba72db`/`c408741` — older docs and `test/backups/` describe the obsolete per-replica-loop design). `apply_gradient` (`grad_transform.py`) takes the **vmap'd per-name gradient dict**, scatters it into the consolidated `(N, T)` grad buffer in place (`state._consolidated_grads.update_(grads)` — aliased views, no concat), then calls `update` **once** on `state` (which reads the cached device-resident `active_mask` directly — no per-step allocation/H2D copy). `Adam.update` (`adam.py`) handles both the batched (`batch_size != ()`, the ensemble case) and unbound (`()`, via `unsqueeze(0)`) shapes, then dispatches the custom op `torchstrap::adam_step_`.

`adam_step_` and `sgd_step_` are defined and dispatched the way ATen defines `_fused_adam_` / `_fused_sgd_`: both schemas come from the single `TORCH_LIBRARY(torchstrap, m)` in `kernels/csrc/stubs.cpp` (the out-of-tree stand-in for the `native_functions.yaml` entries), and each of the four kernels claims its key from its own translation unit. One op per optimizer, one `.cu` and one `.cpp` per op — there is no generic "optimizer kernel framework", for the same reason ATen has none. Python contributes only the two rules the dispatcher cannot infer from C++. The registrations:

- **CPU** (`csrc/cpu/adam.cpp`, `TORCH_LIBRARY_IMPL(torchstrap, CPU, m)`) — hand-written C++, compiled into `torchstrap.kernels._C` at install. It ports **ATen's CPU `adam_math`** (`native/cpu/FusedAdamKernel.cpp`), *not* the CUDA one — PyTorch itself gives each backend its own formulation, and the CPU one is the better choice on CPU: bias corrections and `step_size = lr/bc1` are computed in **`double`** (which is what keeps `1 - beta2^step` from shedding ~3.7 decimal digits as `beta2 → 1`), and `exp_avg` is a **conditional lerp** that interpolates from whichever endpoint is nearer. `at::vec::Vectorized` fast path when the inner stride is 1 and `scalar_t == opmath_t`; a strided scalar path otherwise, accumulating in `opmath_t` so **bf16/fp16 work natively**. `at::parallel_for` over `(replica, 16k-chunk)` tasks — `kChunk` must stay a multiple of `Vectorized::size()` so the ragged tail lands only at the end of a row, as ATen's cache-line chunking does; a frozen replica is `continue`d, so it is never read or written. **12-60x faster than the PyTorch path** (the larger figure when replicas are frozen).

  **The compile flags in `setup.py` (`_CXX_FLAGS` + `_AVX2_FLAGS`) are numerics, not just speed.** Bit-exactness against ATen requires reproducing how ATen builds this file: `-DCPU_CAPABILITY_AVX2` (+ `-mf16c`, without which `vec_half.h`'s `_cvtsh_ss` fails to inline) to get the real AVX2 `Vectorized` rather than vec_base.h's scalar fallback, and **`-O2` with GCC's default `-ffp-contract=fast`** — matching torch's own `CXX_FLAGS`. Both halves are load-bearing and fail in *opposite* directions: at `-O3` GCC fuses AdamW's `param*(1-lr*wd)` into the final `+ (-step_size)*m/denom` where ATen at `-O2` does not; with `-ffp-contract=off` plain Adam's `grad += param*wd` fails to fuse where ATen's does. Either way, 1 ulp. Correspondingly, do **not** rewrite an `a + b*c` in that file as an explicit `std::fma` — the source form is deliberately ATen's so the compiler makes ATen's choices. (ATen's own file is not internally consistent here: its vectorized body and its scalar tail differ in contraction, and the port reproduces that too.) The AVX2 half is gated on the *build host* having AVX2, since an AOT object can outlive a CPU migration.
- **CUDA** (`csrc/cuda/adam.cu`, `TORCH_LIBRARY_IMPL(torchstrap, CUDA, m)`) — hand-written CUDA C++, compiled into `torchstrap.kernels._C` at install. **The device math is not a port**: `#include <ATen/native/cuda/fused_adam_utils.cuh>` and `at::native::adam_math` is called verbatim, so this kernel and `torch.optim.Adam(fused=True)` put the same source through the same compiler. That is why the old NVRTC build's explicit `fmaf` workaround is gone — NVRTC declined to contract `grad += param * weight_decay` where nvcc contracts it, and compiling with nvcc removes the discrepancy at the root. Bias correction likewise uses ATen's own `pow_`.

  **What is deliberately dropped from ATen** is the whole `multi_tensor_apply`/`TensorListMetadata`/`block_to_tensor`/`block_to_chunk` layer — that exists to batch many separately-allocated tensors into one launch, which `State` already solved by consolidating. A 2-D grid replaces all of it: **`blockIdx.y == replica`, `blockIdx.x == chunk within the row`**, at ATen's own launch shape (`kBlockSize=512`, `kChunkSize=65536`). That mapping is what makes the three things ATen has no concept of cheap: per-replica hyperparameters are block-uniform so each is read once into a register with no integer division inside the loop; per-replica bias correction comes from the `(R,)` `state_steps` in-kernel with no `beta.pow(step)` temporaries; and the freeze test `if (!active_mask[r]) return;` is **block-uniform**, so frozen replicas move zero bytes and are bit-exact by construction (no write-back). `amsgrad` (ATen's `depth` 4 vs 5) and the Adam/AdamW mode are template parameters; `maximize` is a runtime flag.

  **Two access patterns, ATen's own**, each calling `adam_math` with the same argument list: the `kILP`-wide vectorized one via `load_store` when `n % kILP == 0`, `is_aligned` holds and the inner stride is 1; otherwise ATen's ragged element-by-element loop. The only change to the second is that it multiplies in `stride_t` — ATen's `load_args`/`store_args` hardcode an inner stride of 1, whereas `register_vmap`'s `movedim(d, 0)` can hand us a strided `(R, T)` view for `bdim != 0`, and now that C++ owns the dispatch key there is no Python wrapper left to bail out to the reference path. With a unit stride it reduces to exactly ATen's loop, so this is not a third branch.

  **Reaching the vectorized path is `State`'s job, not the kernel's.** The guard is `n % kILP == 0` with `n = T - chunk_offset`, and every chunk offset is a multiple of `kChunkSize` — so `n ≡ T (mod 4)` for *every* chunk of *every* row, and a `T` that is not a multiple of 4 puts the **whole ensemble** on the ragged path, not just the last chunk. ATen cannot avoid this (it does not own the allocation); torchstrap can, because it builds the cat, which is why `state.py` rounds `T` up to `_CONSOLIDATION_ALIGNMENT = 4` (≤3 floats per replica; it also makes every row base 16-byte aligned, satisfying `is_aligned`). Measured at the spirals width, R=100: **3.44 → 3.23 ms** all-active and **870 → 820 µs** at 75% frozen, i.e. +6.6%; CPU is unaffected either way (its ragged tail is ≤7 of 264 705 elements). Alignment 16 was tried and is consistently ~0.6% slower on CUDA for no CPU gain. Before this, *both* shipped examples ran entirely ragged (spirals T=264705, cnn T=37827). `bench_inplace_adam.py::_consolidated_T` applies the same rounding on purpose — dropping it would benchmark a shape training no longer runs.

  **There is nothing to autotune here.** The update is memory-bound (~7·N·T·4 bytes/step); at N=100, T=265k on a 4070 block sizes 128/256/512/1024 all land within 1% of each other. Measured against Helion at that size: **3.23 ms vs 3.29 ms** all-active, **800 µs vs 3.22 ms** with 75% of replicas frozen (4.0×), because frozen blocks retire before touching memory. (Those CUDA figures are post-alignment — see the padding note below. The pre-padding ragged-path numbers were 3.44 ms / 870 µs, which is what older revisions of this file recorded as "3.33 ms / 873 µs".) The old Helion autotuner converged on a pathological `block_sizes=[1,128]` config ~5-6× off the roofline because the bandwidth-saturating candidates hit the 60 s compile timeout — which is why that kernel had to be pinned by hand.

  **Toolchain.** `setup.py` picks the toolkit and host compiler itself rather than trusting `CUDA_HOME`: `_pick_cuda_home` requires the **same CUDA major** as `torch.version.cuda` (torch's bundled `libcudart.so.<major>` is already loaded and wins at runtime; crossing a major is a different library, not a compatibility question), preferring an exact minor, then the newest at or below it. `_pick_ccbin` reads the GCC ceiling out of the toolkit's own `crt/host_config.h` and passes the newest acceptable `g++-N` as `-ccbin`, searching `/usr/bin` **before** `PATH` — a linuxbrew GCC ships libstdc++ headers built against a different glibc and fails deep inside `<ext/concurrence.h>`. `setup.py` prints what it chose as it builds. `-O2` (not `-O3`) for the same contraction reason as the CPU kernel, and `--extended-lambda` because ATen's own headers declare `__device__` lambdas (torch builds ATen with it; the old JIT path got away without it only because `cpp_extension.load` uses `-isystem` where `CUDAExtension` uses `-I`).
- **fake** (`register_fake`, Python) — meta / `torch.compile`.
- **vmap** (`register_vmap`, Python) — so the op composes inside an outer `vmap`. This is why the op returns a dummy `Tensor` rather than `()` like ATen's: `torch.func.vmap` rejects a function that returns no Tensor.

The kernel writes params/moments **in place** over `state`'s consolidated buffers.

**CPU and CUDA results are deliberately *not* bit-equal to each other** — each is bit-equal to `torch.optim.Adam(fused=True)` on its own device, and upstream's two formulations differ. Do not "unify" them: bit-equality with the platform you are actually running on is a guarantee a caller can use, whereas cross-device bit-equality of the *optimizer* buys nothing end-to-end, since the gradients feeding it are far further apart across devices (cuBLAS GEMM vs CPU GEMM) than its arithmetic is.

**The compiler must see ATen's source form, including the parts that look removable.** This is the sharpest lesson from the SGD port, and it cost a debugging cycle. `csrc/cuda/sgd.cu` keeps ATen's `grad_scale_ptr` parameter and its `if (grad_scale_ptr) { g /= *grad_scale_ptr; r_args[kGradIdx][ii] = g; }` branch even though torchstrap always passes `nullptr`. That is **not** dead weight: it is a *kernel parameter*, so nvcc compiles the branch without knowing it is never taken, and the conditional write-back it implies changes register pressure enough to change contraction decisions further down the function. Deleting it made `momentum * buf + (1 - dampening) * g` contract into an fma where ATen leaves it a multiply and an add — 1 ulp, and a hard `torch.equal` failure on the ragged CUDA rows of `test_aten_sgd_parity.py`. The same experiment ruled out two other candidates (a compile-time `nesterov`, an added `if (momentum != 0)` guard); the guard *also* broke parity, on the vectorized path, which is why the momentum-zero replica is handled arithmetically instead. **Corollary: when porting a kernel, transcribe it whole. "This branch is unreachable for us" is not a licence to remove it, and neither is "this bool is always known at the call site".**

**Module layout: `csrc/` owns the operators, `optimizer/` owns the optimizers.** `kernels/_consolidated.py` holds the three reshaping helpers (`lead_squeeze`/`hyp`/`hyp_mask`) that both `register_vmap` rules share; each op still keeps its **own** rule with a real named argument list, because the mapping from `in_dims[i]` to an argument is the part a reader has to check against the schema. After the move to AOT there is almost no Python left in `kernels/adam.py` — the op handle (`torch.ops.torchstrap.adam_step_`), the `register_fake`/`register_vmap` rules, and the Helion kernel as clearly-marked **dead code** (nothing imports or registers it; wiring it back in means one `register_kernel` call and nothing else). `optimizer/adam.py` holds only the `Adam` class.

**`csrc/cuda/consolidated.cuh` and `csrc/cpu/consolidated.h` hold the shared scaffolding and deliberately contain no arithmetic.** They are the analogue of ATen's `MultiTensorApply.cuh`: the CUDA header has `kMaxGridY`, `ConsolidatedBuffers<scalar_t, depth>` (the `TensorListMetadata` stand-in, carrying both strides so a kernel can test `stride_t == 1`), `fill_buffers`, `consolidated_grid(R, T)`, `check_consolidated`, and the `to_hyper`/`to_mask` normalisation of the `(R,)` side inputs; the CPU header has `kChunk = 16384` and `parallel_for_chunks(R, T, mask, fn)`, which drives `fn(r, off, n)` over the live `(replica, chunk)` tasks and `continue`s frozen replicas. **Every optimizer's element math stays in its own `.cu`/`.cpp`** — that is where ATen's formulations differ per optimizer and where bit-exactness is won or lost, and it keeps a parity failure attributable to one kernel. Do not grow these into an "optimizer framework"; ATen keeps `adam_math` and `sgd_math` in separate translation units for the same reason.

**Importing `torchstrap.kernels.adam` imports `torchstrap.kernels._C`**, and that import is what runs the static initializers. `torch._C._dispatch_dump("torchstrap::adam_step_")` shows what is registered and from which file — the fastest way to confirm a rebuild took.

**`hl` (helion.language) is bound through `globals()`**, not by assignment, and this is load-bearing twice over: helion rejects a kernel that closes over anything (`ClosuresNotSupported`), so `hl` inside the kernel body must resolve as a *global* rather than a freevar — which rules out a local of `_helion()`; and a placeholder `hl = None` would be a second declaration, which makes a type checker narrow `hl` to a variable and reject the `amsgrad: hl.constexpr` annotations. The `if TYPE_CHECKING: import helion.language as hl` at the top is what the type checker sees. The kernel itself must be defined *inside* `_helion()` because `@helion.kernel` needs helion at definition time and reads those annotations for real, and helion must stay lazily imported (it pulls in triton).

**Callbacks (`callbacks/`) are plain callables**, not skorch hooks — you drop them wherever you want in the manual loop (there is no driver firing `on_*` methods). Each is constructed once and **lazy-inits** its `(N,)` state from `state.batch_size[0]` on first call; they take what they need **explicitly** (not a shared `History`). `EpochScore()(batch_values, batch_sizes=None) -> (N,)` aggregates per-batch losses into an epoch score; `EpochTimer().tic()/.toc()` times a span; `PrintLog()(**metrics)` prints one tabulated row (header once); `Checkpoint(...)(state, score) -> (N,) improved` snapshots the best-so-far rows to the memmap dir on improvement (+ `.load_best(state)`); `EarlyStopping(...)(state, score) -> bool` does vectorized per-replica miss counting, freezes plateaued replicas via `active_mask`, and returns `True` once all are frozen (+ `.restore_best(state)`); `LRScheduler(policy, **kw)(state, score=None)` writes the new lr in place. `Checkpoint`/`EarlyStopping` are vectorized over the ensemble via `Snapshot` (one epoch-granular sync). The base `callbacks.Callback` is now just a `__call__`-only `Protocol` for typing.

**`LRScheduler` (`callbacks/lr_scheduler.py`)** is **torchstrap-native and vectorized** — not a `torch.optim.lr_scheduler` wrapper (the lr is the per-replica `(N,)` vector at `state.optimizer_state["lr"]`, consumed directly by the fused `adam_step_`). As a callable, `sched(state, score=None)` advances a **per-replica, freeze-aware clock** (`t_ += active_mask`, so a frozen replica holds its last lr), computes the new `(N,)` lr via a **policy** object, and writes it **in place** (`lr.copy_`) — so scheduled LRs flow into the kernel and are checkpointed for free. **Cadence is by placement** (call per-epoch or per-batch); `base_lrs_`/`t_`/the policy are lazily captured on the first call. Policies are vectorized functions of `(base_lrs, t)` — `StepLR`, `MultiStepLR`, `ExponentialLR`, `CosineAnnealingLR`, `LambdaLR`, `WarmRestartLR` (SGDR; its restart-period search is a fixed-length branchless tensor loop, no host sync) — plus a stateful **per-replica `ReduceLROnPlateau`** (one plateau state machine per replica over the `(N,)` epoch `score=`, `torch.where`-vectorized and `active_mask`-gated; impossible with torch's scalar-metric version). `policy=` accepts a class or its name; `**kwargs` pass to the policy constructor. All policy names are exported from `torchstrap.callbacks`.

**`History` (`history.py`)** — a plain `defaultdict` subclass, host-side metrics log (no optree/pytree). Epoch-level metrics are flat lists keyed by name; batch-level metrics live under a nested `batches` dict shaped as list-of-lists-by-epoch (`new_epoch`/`new_batch`/`append_batch`). The **record is always host-only**: `append_batch` stages device tensors in a transient instance-level `_batch_queue` (never serialized), and **the caller** calls `flush_epoch()` once per epoch to bulk-drain them to host — see the sync-discipline note above. JSON via `to_file`/`from_file` (`to_dict` → recursive `_untensor` turns tensor leaves to lists). It is an **optional** recorder now — the callable callbacks don't depend on it.

## Conventions that will bite you

- **Runtime type checking is on package-wide.** `src/torchstrap/__init__.py` calls `beartype.claw.beartype_this_package()`, an import hook that beartype-decorates everything. Type annotations are enforced at runtime, so mismatched types raise instead of being ignored. Custom validated types live in `utils/typing.py`: `Scalar`/`Vector`/`BoolVector` are beartype-validated float/bool tensors of specific ndim; `LoaderT` is the data-iterator protocol.
- **Data iterators yield 3-tuples** `(input, target, sample_weight)` (sample_weight may be `None`), each with the leading replica dimension; the loop's `loss_fn` typically calls `criterion(pred, target, weight=sample_weight)`.
- **Per-batch dtype/device is the caller's job** in the manual loop: move each batch member to `state.device` and cast as needed — float features/targets/weights to the compute dtype, but keep **integer classification targets** in their own dtype for `cross_entropy` (move device only). `stateless.py` still ships a `_move_batch_member`/`DTypeSpec` helper, but nothing calls it automatically anymore.
- The base model on the `StatelessModule` is on the `meta` device — it has no data; weights only exist inside `State`.
